# 实验设计与协作计划

## 协议实现路线

1. 保留课程框架提供的 `protocol.h` API，不修改仿真环境接口。
2. 以 `Lab1-linux/datalink.c` 为主实现 Go-Back-N。
3. 将停止等待版本中的单个 `frame_nr` 扩展为发送窗口变量，例如 `ack_expected`、`next_frame_to_send`、`nbuffered`。
4. 为窗口内未确认分组建立发送缓存，超时后从最早未确认帧开始重传。
5. 接收方按序接收 DATA 帧，只交付期望序号的分组，并返回累计 ACK。
6. 所有出站帧追加 CRC，所有入站帧先验证 CRC 再参与状态更新。

## 测试路线

- 基线测试：运行原始停止等待版本，记录吞吐率和日志格式。
- 正确性测试：使用 `-u` 无误码信道，确认分组连续、无重复交付。
- 默认信道测试：使用默认 `1.0E-5` 误码率，确认 CRC 丢弃损坏帧并触发重传。
- 压力测试：使用 `-f` flood 模式观察窗口利用率和吞吐率。
- 高误码测试：使用 `-b 1e-4` 观察重传增加时协议是否仍能稳定运行。
